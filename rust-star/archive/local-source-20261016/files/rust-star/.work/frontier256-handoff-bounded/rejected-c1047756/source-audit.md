# 256K capacity and correctness source audit

Base: accepted score-tile b6b0f125, evidence completion a3010176. Oracle-v5 source/executable, Q2 model and prompt are unchanged. Candidate and runtime claims remain provisional until all live gates pass.

- Continuation FullQ is fixed at 4096 × 32768 FP32 words (512 MiB). HC/normalization/split activations also stay chunk-local. FullKv and compressed histories retain absolute addressing for all 43 layers; no arithmetic or cache-layout optimization is introduced.
- Modeled full histories grow from 13,346,370,048 bytes at 128K to 26,692,645,376 bytes at 256K. The standalone allocation/fill probe successfully touches simultaneous history and selected chunk transients. It excludes the model, other scratch and driver overhead and is not an inference or residency proof.
- Even attention derives 65,536 compressed columns at 256K. A complete 4096-row score buffer is 1 GiB. Top-k derives block count, work width, two scratch halves and merge depth dynamically; its full-chunk scratch upper bound is 2 GiB. Arguments and offsets use 64-bit byte sizes where needed. Intermediate 192K and 4K-step frontiers exercise non-power-of-two selector widths. The retained 8×64 score tile and every imported kernel remain unchanged.
- Odd attention derives mask/key dimensions from compressed rows plus the 4224-row active raw span. The largest modeled mask is 51,380,224 bytes. RoPE's 65536 training-context constant remains unchanged; it is not an execution-capacity guard.
- Rust boundary/adoption validation and four corresponding Metal range checks extend through 262144. Complete handoff still requires the exact last chunk, all 43 saved histories and completed layer 42. The final HC buffer stays 4096 rows. Decoder capacity is frontier+128 and its existing accepted constructor permits up to 1048576+128. Handoff copies the last 128 raw rows and compressed state before releasing prefill history; temporary overlap remains part of the measured memory risk.
- External reference parsing admits aligned 32K–256K prompts extending the immutable 32K token prefix. Both 128K and 256K require 129 complete vocabulary rows; intermediate 192K may use a prefill-only reference and makes no decode claim. All finite values, token bounds and lowest-ID argmax checks remain mandatory.
- The diagnostic --retained option requires all 129 rows. It warms the model once, executes and verifies all output words, resets request state in the same Metal context, then executes and verifies all output words again. The actual residency metadata must report newly established then reused resources. Both per-cycle reference receipts are preserved. It makes no throughput claim.
- Normal engine measurement entry points and their pinned 2K/32K/128K fixtures are unchanged. The new milestone does not enable a 256K performance sample or define new internal HC targets beyond 24K.
