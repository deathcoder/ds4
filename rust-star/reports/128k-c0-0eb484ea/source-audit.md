# Larger-frontier source and claim audit

Candidate `0eb484ea` builds on accepted memory candidate `de6d2c11` (report completion `35f69741`). Oracle source/executable, model and corpus are unchanged.

- `frontier_reference.rs` validates aligned 32K–128K prompt lengths, full vocabulary extents, finite FP32 values, token bounds and lowest-ID greedy selection. A 128K reference must carry all 129 output rows. Reference fields are private outside the crate. Unit tests exercise partial words, invalid frontier lengths, greedy selection, non-finite values and the 128K full-trace requirement.
- `long-prefill-reference-probe` explicitly compares externally supplied vectors. Its output does not authenticate oracle provenance or claim throughput. The evidence runner pins source/binary/model/prompt and authenticates both repeat captures before assigning a C0 conclusion. Existing benchmark commands, built-in fixtures and report writers retain their 32K contract.
- External prompts must extend the immutable 32K token stream. `run_long_prefill_with_reference` preserves initial layers 0..2, the exact layers 3..42 prefix rebuild, and all 43 layers per subsequent 4K chunk. It compares every final prefill word. The same decoder helper now accepts an explicit frontier, seeds the exact selected prefill token, adopts all 43 histories, and compares every word and selection for 128 steps.
- Both Rust and Metal bootstrap-boundary guards now admit aligned rows through 131072. The chunk-start guard, final output-HC extent and complete-prefill adoption guard use the larger range. Adoption requires the final chunk start to equal frontier−4096, all 43 saved layer states and completed layer 42. Decoder capacity is frontier+128; the prepared decoder already supports capacities through 1048576+128.
- Chunk-local Q/HC/norm/split storage from the previous milestone remains at 4096 rows. KV/compressed history and token addressing remain absolute. Full KV histories still scale with context; no sliding-window storage optimization is claimed.
- Native even attention computes compressed columns from chunk_end/4 and allocates its 4096-row score buffer accordingly (512MiB at 128K). `encode_indexer_topk` derives sorted block count, work width, two scratch halves and merge depth dynamically. Rust validates the corresponding dispatch count using the next power of two. Non-power-of-two merge counts occur at intermediate chunks; no fixed 32K selector width was raised blindly.
- Odd attention derives its mask/key dimensions from the current compressed count plus the 4224-row active raw span. RoPE's 65536 original-training-context constant remains unchanged, matching the oracle; it is not an execution-capacity guard.
- No kernel arithmetic changes. New frontier evidence is final-output C0, not new internal HC targets. Existing internal HC acceptance still ends at 24K. Two repeated 128K oracle traces and two complete native traces establish this scoped frontier; they do not establish 256K, throughput or a general serving API.
